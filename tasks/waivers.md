# Waivers

- **B3d, retired-destinations notice in the app (2026-10-25).** `RetiredDestinationsNotice` is tested with injected closures, not against a real vault: the AppTests vault is in memory at the latest schema, and only migration v16 writes `retired_destinations`. Covered instead by VaultStore `retiredDestinationsShowOnceThenClear` (the SQL) and the app's notice tests. Manual check: RELEASING.md #49.
- **B11e, notch island placement and focus (2026-10-25).** `NotchIslandUITests` drives the island on the test Mac's main screen, and `NotchGeometry` is unit-tested for both cases; the hardware notch merge, the island over a full-screen app, its return when FX Vault is activated from another app (`hidesOnDeactivate`), and the system Touch ID prompt from the island need a signed build on a notched MacBook. Manual check before release.
- **D6c2b review, a cancelled sidebar drag (2026-10-26).** `SidebarResizeHandle` keeps its start width in `@GestureState` and ends the drag when that resets, so a drag cancelled without `onEnded` (⌃⌘S mid-drag) still saves its width once. SwiftUI gestures don't fire from synthetic events offscreen, so only the model side is tested (`MainViewModelTests.draggingTheSidebarSavesItsWidthOnce`; `endSidebarDrag()` after `onEnded` is a no-op). Manual check: RELEASING.md #56.
- **D6d banners, the connectivity strip's placement (2026-10-26).** The strip is drawn once in `MainScreen`'s column under the toolbar panel, outside `DetailColumnView`, so every place gets it; SwiftUI exposes no view tree to assert that offscreen. Tested: the texts (`ConnectivityTests.bannerStates`) and the line (`MainScreenPresentationTests.aStatusStripReadsTitleThenDetail`). The snapshots `main-offline` (home) and `main-github-not-responding` (an environment) only write PNGs for review. Manual check: RELEASING.md #64 (every kind of place).
- **S1, Open at login against the real system (2026-10-26).** `LoginItemManager` calls `SMAppService.mainApp`; registering it from a test would add the test host to the Mac's Login Items, so the tests drive `RecordedLoginItem` (on, needs approval, refused, changed in System Settings) and the live call is a manual step (docs/RELEASING.md #65). The shortcut recorder's NSEvent monitor is covered by `SettingsUITests.testTheQuickVaultShortcutRecordsANewKey`.
- **N1 review, a revealed value in the notes can't be selected (2026-10-26).** `PlaceNotesView` draws it with `.textSelection(.disabled)` (as `MaskedValueCell`), so ⌘C, Copy and Services can't reach the pasteboard around `ClipboardManager`. SwiftUI exposes no selection state offscreen, and an XCUITest would need a revealed value (a reauth sheet) plus pasteboard reads, which flake. Tested: the reveal itself (`NotesRevealTests`). Manual check: RELEASING.md #66.
- **F1, dropping a file from Finder on a place (2026-10-26).** XCUITest can't drag a Finder file into the app, and SwiftUI's `onDrop` can't be driven offscreen. Tested: what the drop does once it has a URL (`FileSecretTests.aPlaceOpensTheSheetForKeyFilesOnly`: a key file opens the sheet with it, another file gets the alert) and the sheet over that URL; `FileSecretUITests` covers Choose…. Not tested: the overlay while dragging and the `NSItemProvider` URL load. Manual check: RELEASING.md #68.
- **N2, the notes editor on screen (2026-10-26).** The editor's logic runs offscreen against a real `NotesTextView` (`NotesEditorTests`, `NotesEditAnalysisTests`, `NotesEditSessionTests`), but not what only shows on screen: the Set value… `NSPopover` opening on a token click, its Paste (the system `PasteButton` acts only on a real click, so its clearing of the clipboard is checked by hand), Generate and Kind controls and Done ⌘↩ (their actions are the tested `commitValue` / `moveToVariables` / `NotesValueGenerator`; its capture protection is `setValueStaysOutOfScreenCapture`), the "Discard N unsaved changes?" dialog (its buttons call the tested `discardNotesEdit` / `keepEditingNotes`), the token chips, squiggles, line notes and caret band drawn at TextKit 2's line frames, and VoiceOver reading a line's note (an overlay, not part of the text view). Rendered by the opt-in `VisualSnapshotTests.mainWindowNotesEdit` and checked by eye in light and dark. `NotesEditUITests` drives a click on a line, a typed variable, a secret through Set value… (its first key kept), the header's count, Review ⌘S and Save; it passes on this Mac. Manual check: RELEASING.md #70.
- **N2 review, uppercase Base32 pasted among the secrets (2026-10-26).** A pasted word that passes as a name is taken as a value when `CredentialClassifier` finds a known token prefix or high entropy with a lowercase letter (`NotesPasteParser.looksLikeValue`). An uppercase Base32 seed (a TOTP secret) has no lowercase letter, like `AWS_S3_BUCKET_NAME_2`, so it still pastes as a name: telling the two apart would flag ordinary uppercase names. Tested: `aValueThatPassesAsANameOpensSetValue` (Base64 with one `=`, unpadded Base64, hex, `ghp_`, `sk_live_`), `aKeyVaultTakesDashedKeysAsValues`, `namesStillPasteAsNames`. The line then says nothing wrong; Review lists it as an added name, which is where to catch it.
